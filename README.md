## 🧭 Project Overview

주정차 차량, 트럭, 담장 등에 가려진 보행자는 운전자 시점에서 늦게 보일 수 있습니다. **BlindGuard AI**는 인도를 보는 도로변 엣지 카메라로 보행자의 **차로 진입 시간 창**을 추정하고, 스마트폰 GPS로 계산한 차량의 접근 시간 및 현장 가시거리 $D_{vis}$를 결합해 경고가 필요한 운전자에게 알리는 프로젝트입니다.

현재 목표는 **보행자 탐지 → 동작·차로 진입 판단 → 경고 전달**까지 이어지는 파이프라인을 구현하고, 시뮬레이션과 측정 데이터를 통해 적시성과 오경고를 평가하는 것입니다.

> **Research question**  
> 차량에서 가려진 보행자의 차로 진입을 얼마나 일찍 예측하고, 적시 경고를 유지하면서 불필요한 경고를 얼마나 줄일 수 있을까?

### 🎯 Target Scenario

`트럭 뒤 보행자 → 인도에서 차로 접근 → 진입 예상 시간 계산 → 접근 차량 확인 → 운전자 경고`

진입 경계는 단순한 연석선이 아니라 **실제 주행 차로의 경계**를 기준으로 설정합니다. 첫 단계는 차로 진입 *전* 보행자 경고이며, 이미 차도 안에 있는 모든 사람에게 일괄 경고하는 시스템을 목표로 하지 않습니다.

## ✨ Core Ideas

| 영역 | 접근 방식 |
|---|---|
| 사각지대 관찰 | 인도를 보는 도로변 카메라로 보행자와 주행 차로 경계를 관찰 |
| Vision 연구 | 탐지·추적 결과에서 이동 방향과 차로 진입 의도를 분석하고 진입 시간 창을 예측 |
| 선택적 경고 | 보행자의 진입 시간과 차량 접근 시간이 겹치며, 운전자의 가시거리 $D_{vis}$가 정지 거리보다 짧을 때 경고 |
| 시스템 검증 | 시뮬레이션 및 실제 영상에서 적시 경고, 불필요 경고, 전체 지연을 측정 |

차량에 가려진 보행자를 인프라에서 관찰하는 것과 보행자 횡단 의도 예측 자체는 이미 연구된 주제입니다. 이 프로젝트는 **도로변 카메라의 관찰 결과를 운전자별 경고로 연결하는 전체 흐름과 그 실효성**을 검증하는 데 집중합니다.

## 🧩 System Pipeline

| ① 관찰 · Edge | → | ② 예측 · Vision | → | ③ 선별 · Server / App | → | ④ 경고 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 인도 카메라로 보행자 탐지·추적 | | 차로 진입 시간 창 추정 | | 접근 차량 선택 및 GPS·가시거리 판단 | | 필요한 운전자에게 알림 |

- **Edge / Vision:** 보행자를 추적하고 차로 진입 시간 창 $T_{ped}$를 추정합니다. 시작점은 거리·속도 기반 규칙이며, 확률적 진입 예측 모델은 비교 연구 대상입니다.
- **Server / App:** 스마트폰 GPS에서 차량 도착 시간 창 $T_{veh}$를 계산합니다. 두 시간 창의 겹침과 $D_{vis} < D_{stop}$ 조건을 함께 검토합니다.
- **Simulation:** Webots에서 가림 상황을 재현하고 구간별 운전자 가시거리 $D_{vis}$를 측정할 계획입니다.

> 이 구조는 개발 목표입니다. 실제 장비의 처리 속도와 경고 지연은 통합 실험으로 확인할 예정입니다.

## 📊 Evaluation Plan

| 지표 | 확인할 질문 |
|---|---|
| 적시 경고율 | 운전자가 대응 가능한 시점에 필요한 경고가 도착했는가? |
| 불필요 경고율 | 진입하지 않는 보행자, 도착 시간이 겹치지 않는 차량, 이미 볼 수 있는 상황에 경고하지 않았는가? |
| 탐지·추적 성능 | 먼 거리, 작은 보행자, 가림 상황에서 놓치지 않는가? |
| End-to-end 지연 | 촬영부터 앱 알림까지 실제로 얼마나 걸리는가? |

기본 비교는 **① 반경 내 일괄 경고 → ② 진입·도착 시간 창 매칭 → ③ 시간 창 + $D_{vis}$ 조건** 순서로 수행할 계획입니다. 핵심은 적시 경고율을 유지하면서 불필요 경고율이 얼마나 줄어드는지입니다. 성능 수치는 실험 후 공개합니다.
